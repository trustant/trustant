# End-to-End Tests

End-to-end tests live under `tests/` and are opt-in. They are not part of
`go test ./...` because they interact with a live Trustable/Nuvolaris cluster,
may create app users, launch OpenCode/Vite, and drive a browser.

## Issue 98 guardrail test

`tests/e2e_issue98.sh` runs the Playwright spec
`tests/issue98.spec.mjs`.

The test must use browser-visible FQDN hosts for browser/API requests:

- `trustable.<domain>` for Trustable UI and `/api/*`;
- `opencode.<domain>` for browser-visible OpenCode requests;
- `vite.<domain>` for browser-visible app checks after launch/deploy.

Pod-local checks must stay explicit:

- `kubectl exec trustable-0 -c trustable -- ...` for reading app workbench files
  and running `check_openserverless_actions.sh`;
- `http://localhost:5173` only from inside the Trustable pod, where
  `ops ide devel` runs.

The script detects `<domain>` from `trustable-ing`, then from the Nuvolaris
apihost annotation, and finally falls back to `miniops.me`. Callers may override
this with `TRUSTABLE_E2E_DOMAIN`.

The test can run in two modes:

- Existing app mode: `TRUSTABLE_E2E_APP=<name> ./tests/e2e_issue98.sh`.
- Fresh app mode:
  `TRUSTABLE_E2E_REPO=<org/repo> [TRUSTABLE_E2E_PASSWORD=<password>] ./tests/e2e_issue98.sh`.

Fresh app mode may delete the created app at the end. Set
`TRUSTABLE_E2E_KEEP_APP=1` to preserve it for debugging.

The issue 98 runner must always call `DELETE /api/launch` at the end to stop
the OpenCode and Vite processes it started. In existing app mode it must not
delete the app repository.

The issue 98 E2E must verify at least:

1. Trustable UI loads through `trustable.<domain>`.
2. `/api/launch/<app>` succeeds and returns `encdir`, `b64dir`, `left=4096`,
   and `right=5173`.
3. `opencode.<domain>/project` exposes only the launched app and its canonical
   workbench path.
4. `opencode.<domain>/session?directory=<encdir>&roots=true&limit=10` lists a
   session for the canonical workbench path.
5. `opencode.<domain>/mcp` includes `openserverless`.
6. `<workbench>/<app>/AGENTS.md` exists and contains the Trustable-managed
   block that explicitly demotes `CLAUDE.md` and other legacy/template agent
   files from mandatory Trustable instructions.
7. `<workbench>/<app>/opencode.json` contains:
   - instructions pointing first to `.openserverless-contract.md`, then
     `opencode.md`; the test should compare their `realpath` values with the
     canonical workbench path because `/home/trustable/workbench` may be a
     stable symlink into `/home/trustable/workspace/workbench`;
   - `mcp.openserverless.command == ["openserverless-mcp"]`;
   - permission denies for `packages/**/__main__.py`, `packages/**/*.zip`,
     `ops action`, and `ops action *`.
8. `timeout 60 check_openserverless_actions.sh .` passes inside the app
   workbench.
9. The pod-local dev server responds at `http://localhost:5173` from inside the
   Trustable pod.
10. `vite.<domain>` responds after launch/deploy.

The runner also includes an opt-in second layer for model behavior. It is
disabled by default because it can consume tokens, depends on the selected
model/provider, and may take several minutes.

Set `TRUSTABLE_E2E_RUN_PROMPT=1` to enable the prompt-driven test. The test must:

1. launch or create the target app using the same app-selection rules as the
   fast guardrail test;
2. send `TRUSTABLE_E2E_PROMPT` to
   `opencode.<domain>/session/<id>/prompt_async`, or a read-only default prompt
   that asks OpenCode to run `timeout 60 check_openserverless_actions.sh .`;
3. poll OpenCode session messages and status until the new prompt has produced
   assistant text and no tool remains running;
4. fail on pending OpenCode questions;
5. fail on pending permissions unless `TRUSTABLE_E2E_AUTO_APPROVE=1` is set, in
   which case each permission may be replied with `once`;
6. inspect only the messages created by the current prompt, so historical
   session messages cannot create false positives;
7. require at least one tool call unless `TRUSTABLE_E2E_PROMPT_EXPECT_TOOLS=0`
   is set;
8. fail on tool errors unless `TRUSTABLE_E2E_PROMPT_ALLOW_TOOL_ERRORS=1` is set;
9. fail when a shell tool uses raw `ops action` or `ops action *`;
10. optionally require OpenServerless action MCP usage when
    `TRUSTABLE_E2E_EXPECT_OPENSERVERLESS_TOOL=1` is set;
11. rerun `check_openserverless_actions.sh .` after the prompt;
12. optionally require a changed worktree when
    `TRUSTABLE_E2E_PROMPT_EXPECT_CHANGES=1` is set.

The prompt layer should normally be run with a targeted grep:

```bash
TRUSTABLE_E2E_RUN_PROMPT=1 \
TRUSTABLE_E2E_APP=<app> \
./tests/e2e_issue98.sh --grep 'OpenCode prompt'
```
